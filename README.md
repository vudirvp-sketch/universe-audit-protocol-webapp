# Протокол Аудита Вселенной

**Инструмент качественного аудита вымышленных миров.** Не оценка идеи и не генератор лора: протокол проверяет, что в мире истинно, какие у этого системные последствия, где они превращаются в чей-то прожитый опыт — и что исправлять в первую очередь. Вердикт качественный: семь диагностических полос вместо процентов и баллов. Статический SPA на Next.js, бэкенда нет — ключ API остаётся у вас.

## Какую проблему это решает

Обычная критика мира отвечает «нравится / не нравится» и ничего не говорит о том, где именно конструкция не держит вес. Аудит разбирает три уровня подряд:

- **Мир не порождает последствий.** Заявлено «магия имеет цену», но нигде не видно, кто эту цену платит и что меняется. Лечится прослеживанием причинной цепочки, а не добавлением деталей.
- **Последствия есть, но никого не касаются.** Система работает в вакууме: нет биографий, быта, институтов, которые её переживают. Лечится материализацией — от правила мира к прожитому состоянию персонажа.
- **Ошибку не видно изнутри.** Мир «вроде нормальный», но непонятно, что чинить. Лечится диагностикой по фиксированным измерениям: симптом → корневая причина → приоритетная правка.

Протокол ведёт по этим уровням последовательно и **не выдаёт числовых оценок**: вместо баллов — семь диагностических полос и слово уверенности.

## Что внутри

Отчёт собирается из пяти блоков. Блоки идут строго последовательно, каждый следующий видит сжатые выводы предыдущего:

| # | Блок | Разделы протокола | Что проверяет |
|---|------|-------------------|---------------|
| **1** | Контекст и скелет | §2, §4–6 | Режим аудита, нарративный движок, гипотеза об авторстве, скелет мира, быстрый экран из 7 вопросов |
| **2** | Механика мира | §7.1–7.12 | Пространство возможностей, причинные цепочки, остаток, давление и смещение, связность, абляция, возмущение |
| **3** | Эпистемика и человек | §8–12 | Слои истины, распространение информации и утечка знания, расхождение перспектив, абляция протагониста, культура, психология |
| **4** | Опыт, история, тема | §13–17 | Человеческая поверхность, телесность, ёмкость историй, тематический закон, целостность развязки, соответствие медиуму |
| **5** | Корневые проблемы и рекомендации | §18, §21–27 | Классификация отказов, сжатые корневые проблемы, до 5 приоритетных вмешательств, граница возможного, финальный вердикт |

Всего **13 запросов** к модели (1 + 4 + 3 + 3 + 2): блоки 2–5 разбиты на части, чтобы укладываться в таймауты бесплатных тарифов. Обрезанный ответ модель дописывает сама — до двух продолжений на часть, с отметкой `обрезано` в заголовке блока, чтобы неполный раздел никогда не выглядел полным.

### Вердикт

Семь диагностических полос плюс слово уверенности — без процентов, счётчиков `X/52` и круговых диаграмм:

```text
ОСНОВА МИРА:               слабая / развивающаяся / связная / сильная
СИСТЕМНАЯ ГЛУБИНА:         слабая / развивающаяся / связная / сильная
ЧЕЛОВЕЧЕСКАЯ ИНТЕГРАЦИЯ:   слабая / развивающаяся / связная / сильная
ОПЫТНАЯ ИНТЕГРАЦИЯ:        слабая / развивающаяся / связная / сильная
ЁМКОСТЬ ИСТОРИЙ:           узкая / сфокусированная / широкая / порождающая
ИДЕНТИЧНОСТЬ:              размытая / намечающаяся / отчётливая / уникальная
ОБЩЕЕ СОСТОЯНИЕ:           хрупкое / жизнеспособное / прочное / необычайно порождающее
УВЕРЕННОСТЬ:               высокая / смешанная / низкая
```

Это диагностические полосы, а не объективная оценка качества. Каждая находка несёт метку доказательности — `EXPLICIT`, `DERIVED`, `INFERRED`, `HYPOTHESIS` или `UNKNOWN`, — и молчание материала само по себе дефектом не считается.

### Три режима аудита

- **Быстрый** (по умолчанию) — на входе только концепт.
- **Рамки аудита** (необязательно) — жанр, аудитория, целевой опыт, незыблемые столпы, известные слабости. Рамки меняют веса разделов, но не причинный стандарт: заявленная рамка всё равно проверяется по материалу.
- **Дополнительные материалы** (необязательно) — два и более артефакта превращаются в отдельные слои доказательств, а расхождения между источниками докладываются, а не заглаживаются.

Пустые поля опускаются, так что нетронутая форма воспроизводит обычный аудит.

### Экспорт

Markdown, JSON и печатный HTML одним файлом. Ни один экспорт не содержит баллов, процентов или счётчика `X/52`.

## С чего начать

1. **[Открыть приложение](https://vudirvp-sketch.github.io/universe-audit-protocol-webapp/)** — ничего не устанавливается, весь интерфейс на русском.
2. **Настроить провайдера**: шестерёнка в шапке → провайдер → способ подключения → ключ API → сохранить. Ключ хранится только в вашем браузере.
3. **Вставить концепт** (минимум 50 символов), при желании выбрать тип медиа — нарратив, игра, визуальное, настольная RPG — и нажать «Начать аудит».
4. **Смотреть отчёт** по мере поступления. Полный аудит идёт минутами: это нормально, ход виден в журнале пайплайна с таймерами и сердцебиением каждые 10 секунд.

## Кому подойдёт

- Авторам сеттингов для книг, игр и настольных RPG, которым нужен разбор конструкции, а не список идей.
- Тем, кто хочет проверять мир по причинному стандарту, а не по вкусу читателя.
- Тем, кто работает с собственной моделью или локальным рантаймом и не хочет отдавать текст третьим лицам.

**Не подойдёт**, если нужен генератор лора или сборник готовых идей — это инструмент проверки, а не сочинения.

## Безопасность и ключ API

Бэкенда нет. Ключ и текст аудита не проходят ни через один сервер проекта.

**Где живёт ключ:**

- **По умолчанию** — в `localStorage` браузера. Переживает перезагрузку, но лежит открытым текстом.
- **Только на сеанс** — включите «Не сохранять ключ на диск» в настройках: ключ уходит в `sessionStorage` и умирает вместе с вкладкой.
- **Вообще не в браузере** — запустите локальный relay с переменной окружения `LLM_API_KEY`; браузер ключа не увидит.

**Куда он уходит:**

- **Напрямую из браузера** (по умолчанию) — приложение само зовёт API провайдера. Работает для провайдеров с CORS и для локальных рантаймов вроде Ollama.
- **Через локальный relay** (необязательно) — браузер обращается к `127.0.0.1:8787`, relay пересылает запрос провайдеру. Нужен для провайдеров, блокирующих браузерные запросы.

**Остаточные риски:** ключ, сохранённый на диск, может прочитать вредоносное расширение или кто угодно с доступом к профилю браузера. Режим «только на сеанс» и env-ключ relay — это то, что инструмент предлагает против такого сценария. Внедрённый в вывод модели текст не может выкрасть ключ: HTML отчёта экранируется, сырой HTML из модели отключён.

### Стек

Next.js 16 (статический экспорт, одна страница), React 19, TypeScript, Tailwind CSS 4, компоненты shadcn/ui, состояние на Zustand с сохранением в `localStorage`, тесты на Vitest. Сервера и базы данных нет — это принципиально, а не временно.

### Структура

| Путь | Назначение |
|------|-----------|
| `src/app/` | единственная страница и layout |
| `src/components/audit/` | форма, отчёт, карточка вердикта, журнал пайплайна, настройки |
| `src/lib/audit/` | пайплайн, промпты протокола, разбор вердикта, экспорт, мост контекста |
| `src/lib/llm-client.ts` | провайдеры, стриминг, авторизация |
| `src/lib/i18n/ru.ts` | все строки интерфейса — единственная локаль |
| `relay/relay.mjs` | необязательный локальный сервер: статика и прокси API |
| `docs/protocol/` | канонический документ протокола |
| `__tests__/` | 20 файлов, 462 кейсов |
| `.github/workflows/deploy.yml` | сборка, тесты и публикация на GitHub Pages |

### Команды

```bash
npm install            # зависимости (Node 22+)
npm run dev            # dev-сервер на http://localhost:3000
npm run build          # статический экспорт в out/
npm test               # 20 файлов тестов, 462 кейсов
npm run lint           # eslint
npm run relay          # http://127.0.0.1:8787 — отдаёт out/ и проксирует API
npm run preview        # build + relay одной командой
```

### Локальный запуск без хостинга

```bash
npm run build
$env:LLM_API_KEY = 'sk-...'   # PowerShell; в bash — LLM_API_KEY=sk-...
npm run relay
```

Relay слушает только `127.0.0.1`, прибивает `targetUrl` к хосту заявленного провайдера, проверяет заголовки `Host`/`Origin` и никогда не пишет в лог ключи или тела запросов. Подробности — [`relay/README.md`](relay/README.md).

### Публикация

Единственный канал — **GitHub Pages** через `.github/workflows/deploy.yml`: на пуш в `main` workflow собирает проект, прогоняет тесты и публикует `out/`. Сайт живёт на `https://vudirvp-sketch.github.io/universe-audit-protocol-webapp/`, префикс `NEXT_BASE_PATH` подставляется только для сборки Pages. Никаких других платформ публикации проект не использует.
