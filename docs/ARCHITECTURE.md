# Архитектура и пайплайн

Документ описывает, как устроен аудит изнутри: из чего складываются 13 запросов, как обрабатываются
обрывы и обрезки, что попадает в экспорт. Канонический документ протокола —
[`protocol/UNIVERSE_AUDIT_PROTOCOL_ULTIMATE_v16.md`](protocol/UNIVERSE_AUDIT_PROTOCOL_ULTIMATE_v16.md).

## Две схемы подключения

```
Напрямую:  Браузер (Next.js, статический SPA) ──fetch──> API провайдера
Через relay: Браузер ──fetch──> relay/relay.mjs (127.0.0.1) ──fetch──> API провайдера
```

- **Фронтенд** — статический экспорт Next.js: ни сервера, ни базы данных. Состояние живёт
  в `localStorage` через Zustand `persist`.
- **Relay** (необязательно) — скрипт на Node без зависимостей: отдаёт тот же статический билд
  и проксирует `/api/llm`. Существует только чтобы обойти CORS и убрать ключ из браузера.
- **Ни Cloudflare, ни аккаунтов, ни домена** — приложение это просто статические файлы.

## Пять блоков и 13 запросов

Блоки выполняются строго последовательно, без гейтов: все пять доходят до конца, даже если
материал слабый. Разбиение на части нужно, чтобы не упираться в таймауты бесплатных тарифов.

| Блок | Частей | Разделы протокола |
|------|--------|-------------------|
| 1. Контекст и скелет | 1 | §2, §4–6 |
| 2. Механика мира | 4 | §7.1–7.12 |
| 3. Эпистемика и человек | 3 | §8–12 |
| 4. Опыт, история, тема | 3 | §13–17 |
| 5. Корневые проблемы и рекомендации | 2 | §18, §21–27 |

Итого 13 запросов. Блок 1 внутри себя делает три прохода: контекст и намерение, скелет мира
из 11 строк, затем быстрый экран из 7 вопросов.

Каждый блок отдаёт короткое резюме слабых мест, и оно передаётся следующим блокам — так блоки 2–5
работают не вслепую, а поверх уже установленного.

## Бюджет вывода и продолжения

- Частичный запрос просит **минимум 8192 токена** (или меньше, если таков предел модели)
  и никогда не больше своей доли бюджета блока плюс 2048 запаса. Старое правило делило бюджет
  на число частей, и блок 2 получал 6144 токена на модели с 8192 — это и обрезало разделы
  посреди предложения.
- Если ответ всё равно упёрся в лимит (`finish_reason=length`), клиент просит ту же модель
  продолжить с места обрыва: **до 2 продолжений на часть**, суммарно до 32 000 символов,
  с паузами по RPM и возможностью отмены. Недостающий хвост (обычно вердикт §26.S/§27)
  дописывается в тот же отчёт и в тот же поток.
- **Пауза по RPM**: настраиваемая задержка между частями, `60 / RPM` секунд, минимум 1 секунда.
- **Один ретрай**: на транзиентные ошибки (429, 502, 503) — одна автоматическая попытка через 5 секунд.
- **Спасение частичного текста**: если поток упал после начала ответа, уже полученный текст сохраняется.
- **Разбор вердикта не блокирует**: JSON-блок §27 парсится после блока 5; если он отсутствует или
  битый, качественные полосы восстанавливаются из markdown отчёта (строки таблиц, `LABEL: value`,
  `**LABEL** — value` и заголовки). Отказ разбора никогда не ломает аудит.

## Сколько это идёт и как за этим смотреть

Полный аудит — 13 последовательных запросов. Параллельно ничего не выполняется, а между частями
одного блока клиент выжидает `60 / RPM` секунд (минимум 1 с; при дефолтных 10 RPM это 6 с),
чтобы бесплатный тариф не ответил 429. Один запрос может легитимно стримить минутами:
потолок клиента — 300 секунд на запрос. С учётом продолжений прогон, который починил два раздела,
стоит 14–18 запросов вместо 13.

Тихий запрос и мёртвый запрос выглядят одинаково, поэтому каждая граница докладывается
в журнале пайплайна:

- живая строка статуса над отчётом: прошедшее время, последнее событие и предупреждение
  «тишина N с», если ничего не происходит дольше 10 секунд;
- пока запрос в полёте — строка сердцебиения каждые 10 секунд;
- «Журнал пайплайна» в инспекторе хранит полный список: старт прогона с провайдером, моделью
  и паузой по RPM, каждый запрос с его `max_tokens`, длительностью и числом символов,
  каждую паузу по лимиту, предупреждения об обрезке, продолжения, ретраи и итоги по блокам —
  с кнопкой копирования для багрепорта.

«Отменить аудит» останавливает прогон сразу: прерванный поток не «спасается» как частичный текст,
пайплайн разворачивается, форма возвращается без фоновых запросов.

## Как читать отчёт

Отчёт — один центрированный документ, около 76 символов в строке: строка статуса, заголовки
разделов и текст стоят на одной оси, и заголовок никогда не уезжает под верхнюю панель.
Пока раздел стримится, вьюпорт следует за новым текстом **только если читатель уже внизу**:
прокрутка вверх отсоединяет следование, а плавающая кнопка «К последнему тексту» возвращает его.

Блок, ответ которого остался обрезанным даже после продолжений, помечается `обрезано`
в заголовке (причина — по наведению), чтобы неполный раздел никогда не выглядел полным.
Длинный заголовок аудируемого концепта раскрывается, а машиночитаемый JSON-блок §27 свёрнут
под спойлер — он для инструментов, а не для чтения.

## Экспорт

- **Markdown** — идентичность протокола, авторские рамки, таблица качественного вердикта
  (полосы, уверенность, счётчики, граница возможного, заключительное утверждение),
  все пять блоков, метаданные сессии.
- **JSON** — `protocol`, `input` (`text`, `mediaType`, плюс `guided` / `materials`),
  `meta`, `orientationContext`, `verdict` и пять блоков.
- **HTML** — печатный отчёт одним файлом с теми же рамками, вердиктом и содержимым блоков.

Ни один экспорт не содержит баллов чек-листа, процентов или счётчика `X/52`.

## Каталоги моделей

Список моделей не захардкожен. Экран настроек грузит актуальный каталог провайдера с его
`/models` и кеширует на 24 часа; кнопка обновления запрашивает заново. Встроенный список
используется только когда запрос невозможен (нет ключа, relay недоступен, CORS или сеть),
и интерфейс говорит, откуда взялись данные. Пределы контекста приходят из `llm-client.ts`;
если провайдер их поменял — переопределяются в «Расширенных настройках».

## Языковой контракт

Промпты к модели — на русском. Ключи JSON и значения перечислений — на английском.
Текст для пользователя — на русском. Комментарии в коде — на английском. Это следует
языковому контракту протокола (v16 §1.9).

## Тесты

20 файлов, 462 кейсов. Покрыто:

- экспорт: идентичность протокола, сериализация вердикта, пять блоков, экранирование HTML,
  отсутствие любых артефактов оценки;
- обработчик ошибок: все классы `AuditErrorType`, ретраи, русские сообщения, отмена;
- стриминг: разбор SSE, извлечение дельт по провайдерам, нормализация `finish_reason`,
  обрезанные потоки, продолжение по `length`;
- мост контекста и промпты: извлечение ориентации, детерминированный режим, ограждение материалов;
- пайплайн: последовательность блоков, чанкинг, спасение частичного текста, журнал, статусы;
- разбор вердикта: JSON §27 и все markdown-фолбэки, защита от выдумывания;
- relay: отдача статики, привязка хоста, инъекция авторизации, стражи `Origin`/`Host`,
  env-ключ, лимиты тела, отсутствие ключей в логах;
- безопасность клиента: валидация URL relay, заголовки авторизации, хранение ключа.
